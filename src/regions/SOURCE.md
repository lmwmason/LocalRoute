# 전국 행정구역 선택 데이터와 연결 안내

## 공식 출처와 이용 조건

- 제공: 행정안전부 주민과, [지역별(행정동) 성별 주민등록 인구증감](https://www.data.go.kr/data/3033254/fileData.do).
- 기준일: **2026-09-30**. 포털 등록·수정일 2026-10-02, 확인·다운로드 2026-10-17. 월간 자료의 지역명·행정기관코드만 추출했다. 인구 값은 앱에 포함하지 않는다.
- 포털은 전국 시도/시군구/읍면동 자료로 설명하며 **무료, 이용허락범위 제한 없음**을 명시한다. 별도 API 신청·키·유료 호출 없이 공개 파일을 다운로드했다. 이는 Kakao 데이터나 Kakao 이용 권한에 의존하지 않는다.
- [원본 CSV 다운로드](https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000007706230&fileDetailSn=1&insertDataPrcus=N). CP949, 328,510 bytes, SHA-256 `ad9cd470854f3e72cf604d49751e8de26fbe4966c214bb819f98d5a018501e75`.
- 변환: Python `csv.DictReader`로 CP949 CSV를 읽고 `행정기관코드, 시도명, 시군구명, 읍면동명` 순서의 문자열 배열만 UTF-8 JSON으로 저장. 원본 행을 삭제·병합하거나 지역 이름을 만들어 넣지 않았다. 코드는 숫자로 변환하지 않는다.
- 결과: 3,620개 행정동 행, 16개 시도명, 256개 `(시도명, 시군구명)` 그룹(세종의 빈 시군구 그룹 포함). 17개 시도를 가정하지 않는다. 세종의 시군구명은 원문에서 비어 있으므로 가상의 하위 시·구를 만들지 않는다. 일반구는 원문대로 `수원시 장안구`처럼 표시한다. 법정동·법정리는 행정동으로 오인해 추가하지 않는다.
- 앱의 선택기 아래에도 공식 출처 링크와 기준일을 표시한다. 한국어 공식 이름을 영어 사용자에게도 그대로 표시하고 안내·상태·오류만 번역한다. 확인되지 않은 영문 지명을 생성하지 않는다.

이 자료는 **명시된 날짜의 전국 스냅샷**이며 실시간 행정구역 조회가 아니다. [행안부 2026-10-12 시행 변경 공지](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=130109)도 확인했다. 평택 고덕동 분동 등 기준일 이후 변경은 이 스냅샷에 반영되지 않는다. 해당 게시물의 개별 재배포 허락 표시를 확인하지 못했으므로 첨부 파일을 무제한 이용 자료로 간주해 합치지 않았다. 다음 공개·이용 조건이 확인된 전국 파일로 목록을 갱신해야 한다. 화면은 기준일 이후 변경은 갱신 후 선택 가능하다고 안내한다. 현재 자료를 최신 실시간 목록으로 소개해서는 안 된다.

## 저장 계약과 추천 범위

`HomeRegionFields`는 기존 `Locality`의 `homeCity`, `homeArea`, `localityScope` 세 필드를 그대로 내보낸다. DB 마이그레이션이나 서버 계약 변경은 없다.

- 충청북도 → 충주시 → 살미면: `충주시 / 살미면 / auto`. 기존 정책대로 자동 추천 범위는 충주시 전체다.
- 서울특별시 → 성동구 → 세부 선택 없음: `서울특별시 / 성동구 / auto`. 기존 정책대로 자동 추천 범위는 성동구다.
- 서울특별시 → 성동구 → 성수1가제1동: `서울특별시 / 성동구 성수1가제1동 / auto`. 기존 `구$` 자동 정책을 유지하므로 이 경우 도시 전체가 자동 범위이며 미리보기에 표시한다. 사용자가 `area`를 명시하면 선택한 세부 지역 범위다. `city` 명시도 보존한다.
- 경기도 → 수원시 장안구 → 파장동: `수원시 / 장안구 파장동`. 일반구를 잃지 않는다.
- 광역시 안의 군도 `기장군 / 기장읍`처럼 군 전체를 자동 범위로 유지한다. 통합특별시처럼 여러 시·군이 들어 있는 최상위 지역은 시·군·구를 반드시 선택하며, `담양군 / 담양읍`의 범위가 통합특별시 전체로 넓어지지 않는다.
- 세종은 중간 시군구가 없고 시도에서 읍면동으로 바로 선택한다.

여러 단어로 구성된 `homeArea`는 `shared/locality.ts`의 주소 집계에서도 연속된 단어 경계로 비교한다. 기존 SQL 집계의 연속 문자열/단어 경계 방식과 맞춘 변경이다. 기본 자동 범위 정책과 부족 시 확장 정책을 바꾸지 않는다.

**기존 계약의 한계:** 시도 식별자를 따로 저장하지 않으므로 강원·경남의 `고성군`처럼 도시명이 같은 값은 재진입 때 시도 선택이 다시 필요하다. 화면은 이를 자동 추측하지 않는다. 영구적인 시도 구별이 필요한 경우 메인 담당자가 프로필의 비공개 시도 식별자 저장과 서버 집계를 함께 설계해야 한다. 이 변경은 소유 범위 밖이므로 수행하지 않았다.

## 복구와 입력 검증

- 저장된 값이 목록의 유일한 정확한 조합이면 자동 복원한다.
- `서울 / 성동구`처럼 단일 공식 명칭 후보로 복구 가능한 경우 기존 값을 보여주고 **공식 명칭으로 복구**를 눌러 확인받는다. 광주시처럼 실제 동명 도시와 충돌하면 정확한 이름을 우선하고, 모호하면 시도부터 재선택한다.
- 여러 후보·폐지된 이름·일치하지 않는 한국 지역은 기존 값을 보여주고 공식 목록에서 재선택하도록 한다. 미확인 값을 공식 선택으로 처리하지 않는다.
- 해외 기존 값은 **해외 거주 · 직접 입력**을 명시적으로 고르면 값 손실 없이 복구·수정한다. PRD의 해외 거주 계약을 유지한다.
- 시도 변경은 시군구·읍면동, 시군구 변경은 읍면동을 초기화한다. 선택하지 않은 검색어 자체는 저장하지 않는다. 계층 관계는 실제 원본 행 조합으로 확인한다. 유효한 도시·지역 명시 범위는 선택을 바꿔도 유지한다. 하위 선택 초기화로 지역 범위의 대상이 사라질 때만 자동 범위로 돌아간다.
- 이 기능의 검증은 브라우저 선택 UI에 대한 검증이다. 현재 서버는 기존 Locality 텍스트 스키마를 받으며 전국 코드에 대한 서버 검증 기능을 새로 추가했다고 주장하지 않는다.

## UI 연결과 개인정보

기존 가입·프로필에 연결했다. 다른 화면은 아래 계약을 사용한다.

```tsx
const [regionValid, setRegionValid] = useState(false);
<HomeRegionFields
  value={locality}
  onChange={setLocality}
  onValidityChange={setRegionValid}
/>;
// 저장 버튼/핸들러에서 regionValid와 localitySchema를 모두 확인한다.
```

검색·목록 선택은 하나의 combobox다. 열어서 입력하고 결과를 고르면 같은 칸에 선택값이 나타난다. 화살표/Enter/Escape/Tab, 44px 이상의 입력·선택 행, 모바일 스크롤, 읽기 가능한 결과 수, 로딩·오류·재시도·빈 결과를 지원한다. 미선택 검색 중에는 저장을 막고, Escape/포커스 이탈은 검색어를 버리고 기존 선택을 표시한다.

JSON은 같은 출처의 정적 청크로 지연 로드하고 검색은 메모리에서만 한다. 이메일·예약 정보·위치·검색어를 외부 검색에 보내지 않는다. 외부 자동완성·Kakao API·권한 우회·Supabase 변경·신규 환경 변수는 없다. 지역 선택을 거주 인증으로 표시하지 않는다.

추가 요청으로 가입 동의 행 정렬도 `src/components/Login.css`에서 가입 폼에 한정해 수정했다. 체크박스 22px와 문구 첫 줄 22px를 맞추고 행 전체 44px 이상을 클릭 가능하게 유지한다. 동의 내용·상태 계약은 유지한다.
